# Е-Qabyldau

Әкімдіктің бірнеше бөліміне онлайн қабылдауға жазылу жүйесі. React + TypeScript, Node.js HTTP сервері, SQLite.

## Іске қосу

Node.js 24 немесе жаңарақ нұсқа қажет. Жоба бумасында:

```powershell
npm.cmd install
npm.cmd run dev
```

Сайт: http://127.0.0.1:5173. API: 3001. Команда екеуін бірге іске қосады. Әзірлеу кезінде PORT өзгерсе, Vite proxy сол мәнді орта айнымалыларынан немесе .env файлынан автоматты оқиды.

Жиналған нұсқа:

```powershell
npm.cmd run build
npm.cmd start
```

Сайт пен API бірге http://127.0.0.1:3001 мекенжайында ашылады. Іске қосу командалары .env файлын оқиды.

`npm.cmd start` серверді бақылаушымен іске қосады: әр 20 секундта `/api/health` тексеріледі, процесс тоқтаса немесе үш тексеру қатарынан өтпесе, сервер қайта іске қосылады. Қате баптаумен қатарынан 10 рет іске қосыла алмаса, бақылаушы тоқтап, қатені көрсетеді. `npm.cmd run start:direct` тек серверді іске қосады. Операциялық жүйе қайта қосылғаннан кейін іске қосу хостингтің service manager-інде бөлек бапталады.

## Аккаунттар

Қолданыстағы әкімші аккаунты сақталды, логин мен құпиясөз өзгертілмеді. Ортақ құпиясөз жоқ.

Тек бос дерекқорда алғашқы әкімшіні құру:

```powershell
npm.cmd run staff:setup
```

Шыққан жеке сілтеме 24 сағат жарамды, бір рет қолданылады. Әкімші бар болса, команда жаңа аккаунт ашпайды. Бұл құпиясөзді қалпына келтіру құралы емес.

Қызметкерлер «Кіру → Тіркелу» арқылы тіркеледі. Құпиясөз кемінде 15 таңба болуы керек. Әкімші «Қызметкерлер» бөлімінде қызметкерді тексеріп, кемінде бір бөлімді таңдап, «Рұқсат беру» батырмасын басады. Бұл әрекет мәртебені бірден «Расталған» етеді. Нәтиже немесе қате сол қызметкердің карточкасында көрсетіледі; басқа тізімдерді жүктеу батырманы бөгемейді. Қызметкер өз бөлімдерінің жазбаларын ғана көреді. Рұқсат өзгергенде оның ашық сессиялары тоқтатылады.

## Мүмкіндіктер

- «Кабинет → Қауіпсіздік»: ағымдағы құпиясөзбен растау арқылы жаңа құпиясөз орнату. Екі рет енгізу, кемінде 15, ең көбі 128 таңба; бұрынғы құпиясөз қайталанбайды. Өзгергенде барлық сессия мен бұрынғы қалпына келтіру сілтемелері жойылады, қайта кіру керек.
- «Кіру → Құпиясөзді ұмыттыңыз ба?»: логинмен сұрау жіберу. Аккаунт бар-жоғы жарияланбайды. Әкімші «Қауіпсіздік» бөлімінде сұрауларды көріп, қызметкердің жеке басын тексерген соң өз құпиясөзімен 30 минуттық бір реттік сілтеме жасайды. Оны қызметкерге жеке жеткізу керек; SMS/email автоматты жіберілмейді. Сілтеме қайта жасалса, алдыңғысы жарамсыз. Құпиясөзді өзгертуге дейін сессиялар сақталады; жаңа құпиясөз қойылғанда барлық сессия тоқтайды. Жабылған аккаунтқа сілтеме берілмейді; рұқсат өзгерсе, бұрынғы сілтемелер жойылады.
- Әкімшінің кіруін қалпына келтіру — сервердегі `npm.cmd run password:reset -- <логин>`. Команда белсенді аккаунт үшін 30 минуттық жеке сілтеме шығарады. Сілтемені журналға немесе ортақ чатқа салмаңыз. Нақты сыртқы мекенжай үшін `.env` ішіндегі `APP_ORIGIN` дұрыс болуы керек. Алғашқы әкімшіге арналған `staff:setup` бұрынғыдай бөлек құрал.
- «Кабинет → Жүйе күйі»: дерекқор тұтастығы, соңғы тексеру, іске қосылу уақыты, сұраулар мен сервер қателері, backup күйі, соңғы/келесі көшірме, көшірме аралығы мен сақтау мерзімі. Күй 30 секунд сайын жаңарады. Әкімші көшірмені қолмен де жасай алады. Бұл бөлім мен әрекет қызметкерге ашылмайды.
- «Кабинет → Деректер шарттары»: қазақша және орысша өңделетін үлгілер, жеке нобай және жарияланған нұсқа. Ұйым атауы мен телефоны толтырылмайынша, екі мәтін бекітілмейінше және үлгідегі бос өрістер алынбайынша жариялау өтпейді. Қазір ұйым мәліметтері мен ресми мәтінді иелері кейін толтырады; бекіту автоматты белгіленбейді. Азаматтар `#privacy` арқылы тек жарияланған нұсқаны немесе негізгі түсіндірмені көреді. Жазылуда келісім мәтіні, нұсқасы және уақыты сақталады; шарт өзгерсе, келісімді қайта растау керек, толтырылған жеке деректер сақталады.

- Қазақша және орысша интерфейс: жоғарғы жақтағы және кіру терезесіндегі «ҚАЗ / РУС» ауыстырғышы. Тіл өзгергенде жазылу формасы, таңдалған күн мен уақыт, кіру деректері және пікірдің нобайы сақталады. Браузер тек тіл таңдауын сақтайды; енгізілген жеке деректер localStorage-қа жазылмайды.
- Әкімші кабинетінде «Статистика»: бүгінгі күн немесе 366 күнге дейінгі аралық, бөлім сүзгісі, жазылулар, күтілетін қабылдаулар, қабылданғандар, бас тартқандар және келмегендер. Күндер бойынша кесте, бөлімдердің жүктемесі, орташа баға және соңғы 20 пікір көрсетіледі. Есеп қабылдау күнімен, UTC+5 бойынша жасалады және 1000 жазбалық тізім шегіне тәуелді емес. Тек әкімшіге қолжетімді.
- Қабылдаудан кейін бағалау: қызметкер талонды «Қабылданды» деп белгілеп, қабылдау уақыты аяқталған соң азамат «Талоным» арқылы 1–5 баға және міндетті емес 1000 таңбаға дейінгі пікір жібере алады. Бір талонға бір бағалау; талонның телефон нөмірі мен коды немесе бұрынғы жеке кілті қажет. Пікірлерді тек сол талонның иесі және әкімші көреді.
- «Кабинет → Ерекше күндер»: әкімші барлық бөлімге немесе бір бөлімге белгілі күнді жабады не 1–2 қабылдау аралығын және 15/20/30/60 минуттық ұзақтығын қояды. Күндік бөлім ережесі жалпы күндік ережеден басым; жабық бөлім ашылмайды. Ережені өшіру қалған күндік ережелерге немесе апталық кестеге қайтарады. Бұрынғы талондар сақталады; жоспарланған қабылдаулар саны және олардың тізіміне өту көрсетіледі. Ішкі себеп азаматқа берілмейді. Күндерді алдағы 366 күнге жоспарлауға болады; азаматтарға жазылу бұрынғыдай алдағы 90 күнге ашылады.

«Қызметкерлер» бөліміндегі «Кіруді жабу» аккаунттың барлық сессиясын тоқтатып, бөлімдерге рұқсатын алып тастайды. Кейін бөлім таңдап, «Рұқсат беру» арқылы қайта қосуға болады. «Аккаунтты өшіру» растаудан кейін аккаунтты тізімнен толық жояды; азаматтардың жазылулары мен әрекеттер журналы сақталады. Бұл әрекеттер тек әкімшіге ашық; әкімші аккаунтын осы жерден өшіруге болмайды.

- Қабылдау: дүйсенбі–жұма, 09:30–12:30 және 15:30–18:30. Әр қабылдау — 30 минут; соңғы басталу уақыттары 12:00 және 18:00. Әкімші әр бөлімнің екі уақыт аралығын және қабылдау ұзақтығын жеке баптайды.
- «Әкімге жазылу» — осы кестемен жұмыс істейтін бөлек қабылдау кезегі. Бір бөлімге жазылу әкімнің сол уақытын бос емес етпейді.
- Әдеттегі апталық кестеде сенбі және жексенбі жабық, 12:30–15:30 аралығында қабылдау жоқ. Әкімші нақты күнге арнайы кесте қойса, ол сол күннің апталық уақыттарын алмастырады және қажет болса демалыс күнін де ашады. Азамат күнтізбесі мен API бірдей күндік ережелерді қолданады.
- Әр бөлімде бір мезетте бір қабылдау. Параллель қабылдайтын бірнеше маманға арналған сыйымдылық бөлек кеңейтіледі.
- Бос уақыт серверде тексеріледі, қосарланған және кесте өзгергеннен кейінгі қабаттасқан жазылуларға жол берілмейді.
- Уақыт: Asia/Qyzylorda, UTC+5. Жазылу алдағы 90 күнге ашылады.
- Талондар ортақ SQLite дерекқорында сақталады; браузер жадына тәуелді емес.
- Азамат QR коды бар PNG талонды жүктеп алады. «Талоным» бөлімінде телефон нөмірі мен 6 цифрлы талон кодын енгізеді немесе QR код арқылы талонын бірден ашады; қабылдау басталғанға дейін бас тарта алады. Код әр жазылуға бөлек жасалады, дерекқорда тек хэші сақталады. Бір телефонға 5 қате әрекеттен кейін тексеру 15 минутқа шектеледі. Бұрынғы талондардың ID мен ұзын жеке кілті «Бұрынғы талонмен тексеру» арқылы жұмыс істейді.
- Қызметкер қабылдау мәртебесін және азаматқа көрсетілмейтін ішкі ескертуді өзгертеді.
- Күн, бөлім, мәртебе сүзгілері; CSV экспорты; әкімшіге әрекеттер журналы.
- Тізімде ең көбі 1000 жазба, журналда соңғы 200 әрекет көрсетіледі.
- Парольдер salt және scrypt хэшімен, сессиялар серверде, cookie HttpOnly және SameSite=Strict арқылы сақталады.
- Деректерді өңдеуге берілген келісім мәтіні жазылумен бірге сақталады.

Онлайн өтінім басты бетте және мәзірдегі «Онлайн өтінім» сілтемесімен аккаунтсыз ашылады: http://127.0.0.1:5173/#booking. Ұйым атауы мен мекенжайдың бос болуы жазылуды бөгемейді. Алғаш іске қосылғанда «Жалпы қабылдау» және «Әкімге жазылу» қолжетімді болады. Жаңа кестеге көшу бар бөлімдердің уақыттарын бір рет жаңартады; кейін әкімші енгізген өзгерістер сервер қайта қосылғанда сақталады. Жабық бөлімдер қайта ашылмайды, бұрын берілген талондар өзгермейді. Ұйымның жеке шарттары толтырылмаған кезде деректердің осы жүйеде қалай қолданылатыны туралы негізгі түсіндірме көрсетіледі және келісіммен бірге сақталады. Тесттер оқшауланған дерекқор қолданады. Бұрынғы браузердегі сынақ талондары серверге автоматты көшірілмейді.

## Дерекқор мен сақтық көшірме

Әдепкі жол: .data/staff.sqlite. Басқа жол үшін STAFF_DB_PATH орнатыңыз. Жұмыс істейтін базаны OneDrive арқылы бірнеше серверге ортақ пайдаланбаңыз; серверде жергілікті тұрақты диск қажет.

```powershell
npm.cmd run backup
```

Команда .backups бумасына SQLite-тің біртұтас көшірмесін жасап, `quick_check` және `foreign_key_check` арқылы тексереді. Сервер іске қосылғанда көшірме жоқ/ескірген болса, жаңа көшірме жасалады; кейін әдепкіде әр 24 сағат сайын. Көшірмелер 30 күн сақталады. Ескі қызметтік көшірмелер жаңа көшірме тексерілгеннен кейін ғана тазаланады; басқа атаулы файлдар сақталады. Жұмыс істеп тұрған базаның тек .sqlite файлын көшіру WAL-дегі соңғы өзгерістерді өткізіп жіберуі мүмкін.

`.env`: `BACKUP_ENABLED=true`, `BACKUP_DIR=.backups`, `BACKUP_INTERVAL_HOURS=24`, `BACKUP_RETENTION_DAYS=30`. Баптаулар `.env.example` ішінде бар. Көшірме қатесі кабинетте және сервер журналында көрінеді, автоматты қайталау — 5 минуттан кейін. Дерекқор тұтастығы минут сайын тексеріледі. Backup сервер жұмыс істегенде орындалады; бөлек дискіге/сыртқы қорғалған сақтау орнына көшіруді және сервердің жүктелгенде іске қосылуын нақты хостингте баптау керек.

Көшірмені тексеру: `npm.cmd run restore -- .backups/<backup.sqlite>`. Жаңа файлға қалпына келтіру: `npm.cmd run restore -- .backups/<backup.sqlite> .data/restored.sqlite`. Құрал бар файлды алмастырмайды және негізгі база жолын өзгертпейді. Тексерілген файлды қолдану үшін сервер мен бақылаушыны тоқтатыңыз, `STAFF_DB_PATH` мәнін жаңа файлға бағыттап, қайта іске қосыңыз. Қалпына келтіру сынағы автоматты тестте де, негізгі базаның жеке көшірмесінде де орындалды.

.data, .backups, .env және recovery Git-тен шығарылған. Оларды сайттың ашық бумасына орналастырмаңыз.

## Тексеру

```powershell
npm.cmd test
npm.cmd run lint
npm.cmd run build
npm.cmd run test:security-browser
npm.cmd run test:supervisor
```

Талонның браузердегі толық сынағы (Chrome қажет): `npm.cmd run test:ticket-browser`. Оқшауланған жадтағы дерекқор қолданылады: жазылу, PNG ішіндегі QR кодты декодтау, QR арқылы автоматты ашу, телефон мен қысқа кодпен қолмен тексеру, бас тарту, байланыс үзілгеннен кейін қайталау, әкімші мен қызметкер кабинеттері, сүзгі жауаптарының реті және 320/375/768/1366 px көріністері. Артефактілер `.tmp/ticket-qr-review` бумасына сақталады. Бұл тексерудегі талондар мен аккаунттар нақты дерекқорға жазылмайды.

Тесттер: пароль хэштері, қызметкер рұқсаттары, бір реттік әкімші сілтемесі, cookie және Origin, сессияны қайтару, бөлімдерді оқшаулау, қосарланған жазылу, талон кілті, бас тарту, уақыт белдеуі, кесте қабаттасуы, келісім мәтінінің сақталуы және бос ұйым баптауларымен аккаунтсыз өтінім жіберу.

## Қазіргі шектеулер

Бұл — жұмыс істейтін жергілікті нұсқа. Нақты әкімдік серверіне орналастыру жасалған жоқ. Ұйым деректері мен нақты кестелер кейін кабинеттен толтырылады.

Апталық кестеде екі қабылдау аралығы және олардың арасындағы үзіліс бар. Ерекше күнге бір немесе екі аралық беріледі. Мерекелер автоматты анықталмайды: күндік ережені әкімші өзі енгізеді. SMS, ЭЦҚ, eGov, файл тіркеу және сыртқы жүйелермен интеграциялар қосылмаған.

2026-11-18 жаңартуы: құпиясөздерді басқару, автоматты backup, мониторинг, шарттардың нобайы/жариялануы және кеңейтілген тексерулер. 81 автоматты тест, lint, production build, толық Chrome сценарийі және Chrome/Edge жаңа мүмкіндік сценарийлері өтті. Негізгі база мен құпиясөздер сақталды, көшірмеден қалпына келтіру тексерілді. Толық есеп пен нақты телефондарға арналған қабылдау парағы: [2026-11-18 есебі](docs/readiness-2026-11-18.md). Бұрынғы есептер: [ерекше күндер](docs/special-days-2026-11-16.md), [тілдер, статистика және бағалау](docs/features-2026-11-16.md), [ақаулар мен түзетулер](docs/qa-review-2026-11-16.md).

Нақты енгізу алдында HTTPS сервері, домен, сыртқы бақылау/бөлек сақтау орны, ұйымның бекітілген деректерді өңдеу шарттары және пайдаланушылармен нақты телефондағы қабылдау сынағы қажет. Жергілікті мониторинг пен автоматты backup іске асырылған. Экран өлшемі мен touch эмуляциясы физикалық Android/iPhone және Safari тексеруін алмастырмайды.

Production үшін .env.example үлгісі бойынша NODE_ENV=production, APP_ORIGIN=https://your-domain, STAFF_DB_PATH орнатыңыз. HTTPS кері проксиді Node серверіне бағыттаңыз. Production HTTPS origin талап етеді және Secure cookie қолданады. Әдепкі сервер 127.0.0.1 адресін тыңдайды.

## Қалпына келтіру

Осы көшірмеде src, server, scripts бастапқы бумалары жоқ болғандықтан, олар дайын интерфейс пен бұрынғы README сипаттамасына сүйеніп қайта жасалды. Бұрынғы сайт recovery/dist-original бумасында сақталған. Қолданыстағы аккаунттар жойылған жоқ. Қолданыстағы базаға жаңа кестелер енгізілер алдында .backups бумасына сақтық көшірме жасалды.

## Телефоннан уақытша тексеру

`npm.cmd run share:day` дайын сайтты жинап, Cloudflare арқылы HTTPS туннель ашады. Осы компьютерде ресми cloudflared 2026.10.7 бағдарламасы `.tools/cloudflared-full.exe` жолына орнатылып, GitHub жариялаған SHA-256 хэшімен тексерілген; тексеру деректері `.tools/cloudflared-verified.json` файлында. Ағымдағы URL және тоқтау мерзімі `.tools/share-day.json` файлында көрсетіледі. `status: running` және `health: healthy` сыртқы HTTP тексеруінің өткенін білдіреді; жаңа доменнің DNS тіркелуі біраз уақыт алуы мүмкін. Компьютер қосулы, ұйқы режимі өшірілген және интернеті бар болуы керек.

Байланыс әр 20 секунд сайын тексеріледі. Cloudflare қысқа үзілістерден кейін сол туннель ішінде қайта қосылады; HTTP тексеруі өтпегені үшін бағдарлама тоқтатылып, жаңа сілтеме жасалмайды. Бастапқы 24 сағаттық мерзім сақталады. Мерзім біткен соң жаңа кезеңді тек `node --env-file-if-exists=.env scripts/share-day.mjs --new-day` командасымен ашуға болады.

Cloudflare процесі тоқтатылып, жаңадан іске қосылса, жаңа мекенжай беріледі. Тұрақты мекенжай мен компьютерге тәуелсіз жұмыс үшін домені бар хостинг қажет. Сайтты жаңартқанда `npm.cmd run build` орындаңыз: сыртқы сілтеме әзірлеу серверін емес, `dist` бумасындағы дайын нұсқаны көрсетеді.
