# Ерекше күндердің кестесі

Жаңартылған жергілікті сайт: http://127.0.0.1:3001/ . Әкімші кабинетіне кіріп, **Ерекше күндер** бөлімін ашыңыз.

## Қолдану

1. Күнді және қолданылатын бөлімді таңдаңыз. «Барлық бөлімдерге» жалпы күндік ереже қояды.
2. Күнді толық жабу немесе арнайы қабылдау уақытын қою режимін таңдаңыз.
3. Арнайы уақыт үшін бір немесе екі аралықты және қабылдау ұзақтығын белгілеңіз. Әр аралыққа кемінде бір толық қабылдау сыйып, аралықтар қабаттаспауы керек.
4. Қажет болса ішкі себеп жазыңыз. Бұл себеп азаматтарға көрсетілмейді.
5. Сақтаңыз. Сол күнге жоспарланған қабылдаулар болса, олардың саны мен тізіміне өту батырмасы көрсетіледі.

Ережені тізімнен өңдеуге немесе растаумен өшіруге болады. Өңдеу кезінде күн мен бөлім бекітіледі; басқа күнге жаңа ереже қосылады. Тіл ауыстыру толтырылған форманы тазаламайды.

## Кесте қалай қолданылады

- Бөлімнің жеке күндік ережесі жалпы күндік ережеден басым. Күндік ереже болмаса, апталық кесте қолданылады.
- Бөлім азаматтарға жабық болса, арнайы күн оны қайта ашпайды.
- Арнайы уақыт сол күннің апталық аралықтарын толық алмастырады. Сенбі не жексенбіге де арнайы қабылдау ашуға болады.
- Жабылған күн азамат күнтізбесінде таңдалмайды. Арнайы ашылған күн белгіленеді және оның уақыттары көрсетіледі. Күнтізбені ашқанда күндік ережелер қайта жүктеледі.
- Бос уақыт пен жазылуды қабылдау серверде де сол ережемен тексеріледі. Күндік қабылдау ұзақтығы жаңа талонмен бірге сақталады.
- Бұрынғы талондардың күні, уақыты, ұзақтығы, мәртебесі және жеке кілті өзгертілмейді. Олардың уақыттарын қабаттайтын жаңа жазылу берілмейді. Кесте бұрын жазылғандарға әсер етсе, әкімші олармен бөлек байланысады.
- Ережені өшіру қалған жалпы/бөлім ережесіне немесе апталық кестеге қайтарады; берілген талондарды жоймайды.
- Әкімші бүгіннен бастап 366 күн алға жоспарлайды; азаматтың 90 күндік жазылу шегі сақталады. Уақыт — UTC+5. Мерекелік күндер автоматты толтырылмайды.

## Тексерулер

`npm.cmd test` — **66/66 өтті**. Жаңа сегіз сервер сынағы әкімші рұқсатын, себептің құпиялығын, жалпы және бөлімдік жабуды, басымдықты, бір/екі аралықты, ұзақтықты сақтау мен қабаттасуды, демалыс күнін ашуды, күн шектерін, өңдеу/өшіруді, журналды және жарамсыз мәндерді қамтиды. Бұрынғы көшіру сынағы ереженің SQLite базасын қайта ашқанда сақталуын да тексереді.

`npm.cmd run lint` және `npm.cmd run build` — өтті.

`npm.cmd run test:ticket-browser` — өтті: күнді әкімші формасынан жабу, бұрынғы талонды сақтау, сол күннің жазылуларын ашу, арнайы уақытқа өңдеу, тілді ауыстырғанда деректердің қалуы, жалпы мерекенің күнтізбеде жабылуы, арнайы ашылған сенбіге нақты жазылу, ережені өшіргенде апталық кестеге қайту тексерілді. Орысша бет 320 және 375 px ендерінде тасымайды; JavaScript қатесі 0. Артефактілер `.tmp/ticket-qr-review/special-days-*` және `special-day-booking-mobile.png` ішінде. Бұрынғы толық сценарийлер де өтті.

Негізгі база өзгермес бұрын `.backups/qabyldau-2026-11-16T11-01-25.930Z.sqlite` жасалды. Бастапқы код көшірмесі: `.backups/special-days-20261116-160126`. Жаңартудан кейін бұрынғы 1 аккаунт, 7 жазылу, 5 бөлім және бағалау саны сақталды; `quick_check=ok`, сыртқы кілт қатесі 0. Нақты базаға сынақ ережелері қосылмады.

Сервер қайта іске қосылды: сайт HTTP 200 қайтарады, API сау және жаңа ерекше күндер API-і жауап береді. Сыртқы хостингке жариялау жасалған жоқ.
